## Запуск

На этом компьютере откройте `start.cmd`, затем **http://127.0.0.1:3005**. У шестого дня своя база `workflow_day6`. Предыдущие дни хранятся отдельно. Скрипт запускает локальный PostgreSQL и добавляет отсутствующие seed-записи.

На другом компьютере нужны Node.js 24 LTS и PostgreSQL. Создайте отдельную базу, скопируйте `.env.example` в `.env` и задайте `DATABASE_URL`:

```sh
npm ci
npm run db:init
npm run dev
```

## Что сделано

- Общие компоненты `KnowledgeListing`, `ArticleCard`, `ArticleFeedback`; тексты статей находятся на сервере. Каталог получает только краткие сведения через публичный GET API.
- У каждой публичной страницы свои title, description, canonical и Open Graph. Поисковые варианты страницы имеют `noindex,follow` и canonical без фильтров.
- `public/sitemap.xml` содержит восемь публичных адресов, `public/robots.txt` исключает приватные разделы. Неавторизованный запрос к приватному API всё равно получает 401: robots.txt не защищает данные.
- Оценка статьи восстанавливается из cookie после hydration. Дата выводится одинаково независимо от часового пояса браузера.
- Убрана загрузка логики рабочего кабинета на публичных страницах. Меню загружается при открытии, оценка статьи — при появлении в области просмотра. Подключены сжатие файлов и переменный шрифт.
- Изображение главной использует lossless WebP с PNG fallback, явными размерами и высоким приоритетом. Главную картинку не откладываем: она нужна на первом экране.

Режимы рендеринга, исходные измерения, результат оптимизаций и ограничения описаны в [docs/PERFORMANCE.md](docs/PERFORMANCE.md).

Перед публикацией задайте **свой настоящий адрес** в `NUXT_PUBLIC_SITE_URL` в `.env`, затем выполните `npm run build`. Эта команда обновляет sitemap, robots.txt и изображения. В учебной локальной версии используется `http://127.0.0.1:3005`; внешнего домена и публикации пока нет.

## Что нужно понимать

**SSR** — сервер сразу отправляет HTML с текстом. **Предрендеринг** делает такой HTML заранее при сборке; он подходит для редко меняющихся статей. Страницы поиска остаются SSR, поскольку результат зависит от query-параметров.

**Hydration** — Vue подключает обработчики к готовому HTML. Первая разметка сервера и браузера должна совпадать. Cookie с личной оценкой читается после этого подключения.

**SEO metadata** описывают страницу для поиска и предпросмотра ссылок. Canonical задаёт основной адрес. Sitemap перечисляет открытые страницы. HTTP 404 сообщает, что сущность отсутствует.

**LCP** показывает, когда появился главный элемент; **CLS** — сдвиги макета; **TBT** — блокировку главного потока при загрузке. Сравниваем одинаковые страницы в одинаковых условиях, берём медиану трёх запусков.
